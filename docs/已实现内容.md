## 0. 总体架构（已落地的样子）

```
LLM / Web 面板
   ↓ POST /api/mod/:method（结构化透传）
ModWSClient（steveX 侧 WS 客户端）
   ↓ ws://127.0.0.1:25550  {id, method, params} → {id, ok, data | error}
采集端 mod（真实世界客户端，vendor/stevex-template-1.21.11）
   ↓ 写 <gameDir>/stevex/vision/*.nbt + memory_cells.bin（反向通道）
记忆世界 mod（vendor/stevex-test-template-1.21.11，文件驱动、mtime 门控）
```

三个进程，各自独立窗口：

| 进程 | 启动 | 已实现角色 |
|---|---|---|
| 采集端（真实世界） | `npm run mc:capture` | Minecraft 客户端内 mod，WS 25550，50 方法控制 + 深度缓冲视觉采集落盘 |
| steveX（脑） | `npm start` | Express Web 面板 8090 + mod 方法透传 + WS 广播 |
| 记忆世界 | `npm run mc:memory` | 独立客户端，读 .nbt 复原"冻结的瞬间" |

## 1. 采集端 mod（`vendor/stevex-template-1.21.11`）

Fabric 1.21.11 客户端 mod，Java 21。**功能完整**，除两个空壳类外无未完成实现。

### 1.1 WebSocket JSON-RPC 服务（`AgentWebSocketServer.java`）
- 监听 **25550**（`java-websocket` 实现，`setReuseAddr(true)`），客户端初始化时 `launch()` 启动。
- 协议：请求 `{"id":1,"method":"player","params":{}}`；成功 `{"id":1,"ok":true,"data":{}}`；失败 `{"id":1,"ok":false,"error":"msg"}`；标量结果包一层 `{"value":…}`。
- 未知方法 → `unknown method: xxx`；解析失败 → `invalid message format`。
- **多连接支持**（不做单连接限制，handler 为静态共享注册表）。
- **busy 语义**：`busyMethods` 集合上报，`status` 方法自身不算 busy；`lastError` 静态字段记录最近错误。
- 统一跨线程通道 `runOnClient(timeoutMs, what, action)`：动作投递 MC 主线程并阻塞等待（超时只 warn 不抛）。
- 参数/格式化助手：`bool/num/int/double`、`f1/f2/f3`。

**关键方法返回结构：**
- `player` → `vitals`(health/food/xp/armor/air)、`flags`(onGround/sprinting…)、`effects[]`
- `inventory` → 41 格（含盔甲/副手），每格含 durability/enchantments/food/attributeModifiers/tool/customModelData 等条件字段
- `f3` → `position`(xyz/block/chunk/facing/dimension)、`chunk`、`entities`、`environment`(biome/light/tps…)、`target`(准星方块/流体/实体全量)
- `profiler` → F3+1 性能饼图递归树（节点 name/percentage/globalPercentage/count/children）
- `sound` → 当前播放声音列表（id/source/xyz/volume/pitch…）
- `container/get` → 按菜单类型附专属数据（熔炉进度、附魔花费、村民交易、讲台页码等）
- `container/drag` → 单次 QuickCraft 拖拽相位包（phase 0=begin/1=add/2=finish，type 0=均分/1=每格1/2=克隆），纯原语不取物（语义见 `容器拖拽API设计方案.md`）
- `container/beacon` → 设信标主/副效果并扣支付物（等价信标 GUI"点效果图标+点√"，直接发 `ServerboundSetBeaconPacket`）；params `primary`/`secondary` 为效果注册 id 如 `minecraft:haste`

### 1.3 视觉系统（v2，GPU 深度缓冲驱动，10 个类）

**管线**：`VisionApi.snapshot` → `DepthCapture.requestCapture()`（等待一帧，超时 15s）→ `Unprojector.visibleBlockHits()` 全量反投影 + `MemoryCellsReader.read()` 反向通道 → 主线程 `ObjectResolver.resolve()`（四路查询 + DeletionJudge 减量判定 + v2.31 群系 cell 采样 + 各 Store 落盘）→ 组装 JSON。

- **DepthCapture（深度图采集）**：vanilla 只支持 color 附件回读，故手写 GL——PBO 非阻塞回读 + fence 异步映射，**零卡顿、一帧完成、按需触发**。两个锚点：主深度（`LevelRendererMixin.renderLevel` TAIL）+ translucent 深度（`ChunkSectionsToRenderMixin.renderGroup(TRANSLUCENT)` TAIL，仅 Fabulous）。同帧握手保证深度与实体快照同步；late_debug gizmo 前哨跳过异常帧。
- **Unprojector（像素→世界坐标）**：纯数学。`inversePv` 反投影每像素（跳过天空/近裁剪），产出方块去重点（ε=0.05）+ 实体候选表面点；含 `projectToScreen` 世界→屏幕投影。
- **ObjectResolver（可见对象解析，四路查询）**：① 方块直查 + air 近侧回退（含实体相交验证）；② 方块实体搭方块便车（壁挂朝向过滤）；③ 实体正向像素归属（SectionPos 桶粗过滤 + slab 求交 + 肢体判别 A/B）；③.5 半透明掉落物（Fabulous）；④ 半透明/绊线方块（translucent 深度逐像素分类 + voxel DDA 区间射线推进 + 降级回退）。
- **DeletionJudge（删除判定，v2.23）**：几何证明式——实心不透明格存在时射线必在其近表面终止；"像素深度 ≥ 格远面距离"证明该格已消失。越过计数 ≥ 阈值（默认 2，由 cells 文件头下发）判消失。
- **MemoryCellsReader（反向通道）**：读记忆侧 `memory_cells.bin`（magic "SCEL"，小端），mtime 门控；文件缺失优雅降级为"只增不删"。v2.32：解析 **version=2** 头部（version 后带 UTF-8 维 id）→ `CellsData.dimension`；删除判定只对 `dimension == 本快照维` 的 cells 执行（version=1 旧文件无维标签 → 删除证据置空，宁缺勿滥）。
- **Store 落盘（gzip NBT，`<gameDir>/stevex/vision/`；v2.32 起按维分桶）**：文件顶层统一
  `{ "currentDimension": "<dimId>", "worlds": { "<dimId>": { 本维正文 }, … } }`——快照型只覆写当前维桶、
  其余维桶保留（换维不再清掉上一维"最后可见快照"）；累积型在各自维桶内 union（主/下界同坐标永不互撞）；
  读侧（记忆端）无 `worlds` 键 → 旧单维文件自动视为 overworld 桶。
  - `terrain.nbt`：**每次快照覆写当前维桶**，`blocks` + `deletions`（v2.23）。
  - `entities.nbt`：**覆写当前维桶**，轻量物理状态（不存全量 NBT，全量走 `vision/entity` 按需查询，TTL 1000ms + LRU 256）。
  - `block_entities.nbt`：**增量合并**（new/updated/skipped），全量 NBT；每维桶一份。
  - `biomes.nbt`（v2.31/v2.32）：**单调 union 累积覆写（当前维桶内）**，`cells`：cell key（quart 坐标 `"qx,qy,qz"`）→ biome id（如 `minecraft:plains`）；采样源 = 本帧可见方块集 + 相机 cell 锚点，**逐 cell、绝不逐方块**（同 cell 群系必然相同＝存储保证）；仅对不在 union 的 cell 解析，新增>0 才整体覆写。`snapshot` 的 `storeStats` 含 `biomes:{cells,added}`。
  - `containers.nbt`（v2.28/v2.30/v2.32）：会话化交互内容；`containers`（per-pos）分桶，**末影箱 `enderInventory`（玩家态）保持顶层全局**、跨维同一（真实 MC 末影箱语义）。
  - 各维桶自带 `agentPos/agentYaw/agentPitch/agentFov/dayTime`（姿态随桶存，每维一份）。
  - `snapshot` 响应顶层含 `"dimension"`（v2.32，与 store 的 `currentDimension` 一致）。
- **VisionCollector**：序列化中枢 + Tier-2 实体全量 NBT（`saveWithoutId`）。

### 1.4 Mixins（10 个）

## 2. steveX 大脑（`src/`，Node ≥18，依赖仅 express + ws）

### 2.1 主入口 `main.js`
加载配置 → 创建 `AgentManager` → 启动 Web 服务器 → 处理 SIGINT 优雅退出。

### 2.2 `ModWSClient`（`src/mod/client.js`）
- 完整 JSON-RPC 客户端：请求/响应按 id 配对、超时、心跳无、**指数退避断线重连**（2s→30s）、status 缓存 + `refreshStatus()`。
- `call()` 永不抛异常，返回 `{ok,data}` / `{ok:false,error}`。
- 事件：`connected` / `disconnected` / `status`。
- `src/mod/index.js`：Phase A **单例连接**（getModClient），透传路由共享同一实例。

### 2.3 方法清单 `src/mod/methods.js`
50 个方法的元数据（method/category/description/zh/paramDefs），其中 `paramDefs` 是权威参数 schema
（每项 `name/type/required?/def/hint/sample`，已按 mod Java 源码逐条核实，含此前被误标为 `{}` 的
`container/slot`、`chat/send`、`sign/set`、`book/set` 等真实带参方法）。
`zh` 为查询器逐方法中文说明：**带参方法在文内直接枚举 `params` 可填键**（`?` 标可选，如
`container/slot` →「params 填 { slot, button?, clickType? }」、`vision/entity` →「params 填 { uuid(必填), force? }」），
**无参方法注明「无参数」**；`sample` = 查询器预填 step 模板的示例值（可与 `def` 不同以示可改，如 `camera/turn` 的 `dx` def 0 / sample 90）。
`METHOD_NAMES` 与 `methodsByCategory()` 供前端与状态页复用。`/api/skills` 的 `args` 由 `paramDefs` 派生成 name→type 紧凑对象。

### 2.4 `AgentManager` / `SteveXAgent`（`src/agent/`）
- 每个 agent = 一条到采集端 mod 的 WS 连接（`steveX_改进方案.md` §六 落地）。
- 生命周期：`connectAgent`/`disconnectAgent`/`reload`/`disconnectAll`，事件总线 `eventBus`（agent:connect/update/disconnect）。
- **状态缓存**：每 3s 轮询 `player`+`f3`+`status` 刷新 vitals/position/busy；前端实时展示。
- `getStatus()` 聚合 agent 状态（health/position/currentAction/mod{host,port,connected,busy,error}/model）。

### 2.5 mod 透传路由（`src/web/server/mod_routes.js`）
- `POST /api/mod/*splat`（通配捕获含斜杠方法如 `vision/snapshot`）→ 直传 mod，成功 200 / 失败统一 **502**。
- `GET /api/mod/status`（实时 refreshStatus + connected + 方法清单）、`POST /api/mod`（通用 `{method,params}` 入口）、`GET /api/mod/methods`。
- **批量时序 API**（`src/web/server/mod_batch.js`，设计见 `docs/批量时序API设计方案.md`）：
  `POST /api/mod/batch`（有序 step JSON + 步前 `waitMs`，后台串行执行，立即回 `batchId`）、
  `GET /api/mod/batch/:id`（每步 state/result 进度）、`POST /api/mod/batch/:id/stop`（中止）。
  全局单槽（并发 409 + runningId）、`stopOnError`、结束/中止自动补发 `pressed:false` 松键（`src/mod/pressable_methods.js`）。
  三条 batch 路由注册在 `*splat` 通配**之前**（否则被当地图方法名透传）。

  - Agents 页：agent 卡片（health 条/位置/model/mod 连接态）、**Mod API 查询器**（参考/助写，只读**不执行**，GET /api/mod/methods 填充）——搜索 + 按分类分组的方法下拉，选中后展开 detail：**顶部「语法框」**（`.modapi-grammar`）第一行为该方法的 pill+方法名+中文说明（`.modapi-meta` 内 `zh`，随选中刷新、文内枚举 `params` 可填键），其下为静态 step JSON 写法（`.modapi-grammar-code`），两行虚线分隔；再往下是可编辑 step 模板（预填 `paramDefs.sample` 示例值，无参为 `{"params":{}}`）与逐参数提示行（无参显示「无参数」）；按钮「追加到 Mod Batch」（JSON 校验后并入同卡 batch 文本框）/「复制」。）、搜索/过滤/排序、Agent Log 弹窗（cmd/llm 日志实时追加）、DOM diff 增量渲染。

## 3. 记忆端 mod（`vendor/stevex-test-template-1.21.11`）

Fabric 1.21.11 客户端 mod。核心设计：**文件驱动、mtime 门控，空闲成本≈0**。

### 3.1 整体工作流程
- 客户端启动自动创建/打开**纯虚空超平坦单人世界**（`MemoryWorld`，创造+和平+作弊，`resetOnLaunch` 可重建）。主世界始终虚空；`voidNetherEnd`（默认 true，v2.30）时下界/末地也建成纯虚空（保留各自维度类型/生物群系，仅不生成方块与结构）——生成器只在世界创建时定型，改配置需删除存档或 `resetOnLaunch=true` 重建。
- 每 tick 按序驱动：`TERRAIN.tick`（地形增量）→ `ENTITY.tick`（实体增量）→ `RESTORER.tick`（方块实体增量）→ `CONTAINER.tick`（容器内容对账，v2.28）→ `BIOME.tick`（生物群系复原，v2.31）→ `DELETION.apply`（减量）→ `CELLS.tick`（反向通道写 cells）→ 传送玩家到 agent 视角 + 同步 FOV。
- **v2.32（镜像跟随）**：上述序列每 tick 只驱动**活动维**（= agent 当前维，terrain.nbt 顶层 `currentDimension` 为权威源）的 ServerLevel；记忆玩家随之被传送到同一维，各复原器**只 apply 该维自己的维桶**、内容按维隔离（坐标永不跨维碰撞）。换维时先铺内容、管线底部再跨维传送玩家；未进入的维内容在文件里保留、进入即铺。
- **数据源自动探测**：配置显式路径 → `gameDir/stevex/vision/*.nbt` → **同级兄弟项目** `gameDir/../.. /stevex-template-1.21.11/run/stevex/vision/*.nbt` → 上级嵌套 → 兜底 `gameDir/config/stevex-test/*.nbt`。
- **mtime 门控**（v2.13）：每 `pollIntervalTicks`（默认 1）stat；mtime 未变不读不解压；仅成功读取后推进；半截写保留旧 mtime 重试。第二层**内容指纹门控**（表指纹变化才 sync）。
- 文件缺失不报错、挂起重试（30 tick 告警一次），出现后自动恢复。

### 3.2 `MemoryConfig`
`config/stevex-test/memory.json`（首次自动生成），16 项：worldName / sourceFile / terrainFile / entityFile / pollIntervalTicks / autoOpenOnLaunch / resetOnLaunch / **voidNetherEnd**(=true，下界/末地同主世界纯虚空，v2.30) / **removalEnabled** / **removalPixelThreshold**(=2，随 cells 下发) / removalMaxRayDist(=96) / memoryCellsWriteIntervalTicks / memoryCellsFile / **containerFile** / **containerReconcileOnPoll**(=true，每轮对账，v2.28) / **biomeFile**(v2.31)。

### 3.3 `MemoryWorldManager`
世界创建/打开/删除、`isMemoryWorld`（按世界名判定）、服务器切换清状态、首个玩家 setupPlayer（创造+飞行防掉虚空）、冻结 gamerule（`random_tick_speed=0`、`advance_time=false`、`advance_weather=false`、**`spawn_mobs=false`**，v2.30 §7.9 ⑧——建档时随 LevelSettings 写入 + 首次进入再设，双落点关闭生物自然生成）、`teleportToPose`（脚部-眼高、双精度、NaN 沿用当前朝向）、渲染线程同步基础 FOV。命令 `/memrestore`（GAMEMASTERS）强制重读。

- **v2.32（§5 镜像路由 + 跨维传送）**：新增 `DIM_BY_ID`（vanilla 三维 id → `Level.OVERWORLD/NETHER/END`）白名单、`lastAppliedPose`、`unsupportedDimWarnCooldown`。`onServerTick` 每 tick 以 `TERRAIN.activeDimensionId()`（terrain.nbt 顶层 `currentDimension` 最近一次成功读取值）为活动维权威源，直取 `server.getLevel(key)` 驱动；agent 在未知自定义维 → 300 tick 节流 WARN + 降级驱动玩家当前所在维（内容冻结→复原器近乎 no-op），回 vanilla 维自动恢复；无玩家 → overworld 兜底。gamerule 是**世界级**状态、三唯共享一份存档级规则，冻结设一次即全维生效。复原管线全部跑在活动维 level 后，底部以该维桶 agent 姿态 `teleportToPose(player, level, pose)` 传送玩家（level 是另一维即经 `TeleportTransition` changeDimension 完成换维）；**门控 = 跨维 ‖ 姿态变化**（玩家所在维 ≠ 活动维时无条件传送，同值跨维也须换，防困旧维）。

### 3.4 `TerrainRestorer` + `BlockStateUtil`
- 解析 terrain.nbt：`blocks` 表 + v2.23 新增 `deletions` + `agentPos`（旧文件缺键向前兼容）。
- 静默放置（flags 818 = UPDATE_CLIENTS | SKIP_ALL_SIDEEFFECTS）：不触发邻居更新、无掉落物、无 onPlace 副作用；**只放方块状态不挂 BE**（BE 由 MemoryRestorer 管），防 ghosting 清 stale。
- **纯累积**（只增不删，删除走几何证据路径）。
- `BlockStateUtil`：块 ID 重建 + 属性按序列化名/枚举常量名双重匹配兜底；`isSolidOpaque`（实心+不透明 = 唯一可删对象）。
- v2.32：读按维分桶文件（暴露 `activeDimensionId()` = 顶层 `currentDimension`，镜像活动维权威源）；`applied`/`appliedFingerprint` 按维隔离、mtime 门控 + 读取代际 × 每维一次交付，只 apply `level.dimension()` 维桶。

### 3.5 `EntityRestorer`
解析 entities.nbt（key=uuid）→ 按文件 uuid 强制生成 → 放置 → 移动（差>1e-4 teleport）→ **冻结**（NoGravity/Invulnerable/零速度/Mob NoAI+persistence/Item 无限寿命/登记 FROZEN 集合）。纯累积；减量接口 `allCellsEmpty`/`discard`。
- v2.32：已放置实体 / uuid 表按维隔离（chunk long / uuid 不编码维），`entities(dim)`/`uuids(dim)`/`currentUuids(dim)` 按维取；冻结只对活动维实体判定。

### 3.6 `MemoryRestorer`（方块实体通道）
增量合并 BE，静默放置，agent 视角姿态返回。
- v2.32：BE entries/applied/指纹按维隔离；`tick` 只返回/应用 `level.dimension()` 维桶，姿态（AgentPose）只读该维桶自带 agentPos/朝向/FOV；仅在新内容代际 × 首次驱动该维时返回 pose。

### 3.7 `DeletionApplier`（减量执行器，v2.23 / v2.36）
删除判定**完全在采集侧**（DeletionJudge），本类只执行。顺序**先增量后减量**（防重建）；相机格快路径（仍只删实心不透明）；**假阳性防护**（当前可见集不可删）；v2.36 起 deletion 主循环守卫放宽到 `isDeletableContent`（实心不透明 ∪ 流体（水/岩浆）∪ 满格透明，清 BE）；冻结实体清理需全部 AABB 占用格证空。
- v2.32：`apply` 只对传入的活动维 level 执行——删块/清 BE/实体清理全部限定该维（采集侧 cells 另带维标签双保险，镜像落后时宁缺勿滥）。

### 3.8 `MemoryCellReporter`（反向通道）
每 tick 把记忆世界"当前存在的实心不透明块 + 冻结实体占用格"按距离球过滤，写 `memory_cells.bin`（小端 SCEL；v2.32 起 **version=2**：magic/version/UTF-8 维 id 长度 L/L 字节 dimensionId/threshold/maxRayDist/count/count×BlockPos long），内容指纹门控 + 原子写（tmp + ATOMIC_MOVE）。只上报**活动维**内容并带维标签（采集侧据此只对同维 cells 判删）；活动维尚无玩家（跨维传送过渡 tick）跳过本轮且不推进指纹；`removalEnabled=false` 时纯累积不写。

### 3.9 Mixins（4 个）
- `LevelMixin`（`Level.tickBlockEntities` @HEAD cancellable）：记忆世界**取消全部方块实体 tick**（熔炉/漏斗/刷怪笼/活塞动画冻结在初始态）。
- `ServerLevelMixin`：`tickBlock`（冻结红石/活塞/TNT/火焰/重力方块）、`tickFluid`（冻结流体流动）、`tickNonPassenger`（仅对 FROZEN 实体取消 tick，拦截 TNT 引信/箭矢寿命等分发层计时器）。
- `PortalTravelMixin`（v2.33，`Entity.canUsePortal(boolean)` HEAD cancellable）：记忆世界里传送门旅行**统一闸门**置 false——下界门/末地门/末地折跃门 `entityInside` 不登记进内、`handlePortal` 不放行旅行 → `getPortalDestination`（`PortalForcer.createPortal` 新建出口门 / `EndPlatformFeature` 铺末地平台 / credits）永不执行；客户端 `animateTick`（粒子/声音）照常 → 门=纯装饰。打在基类 `Entity.canUsePortal`，LivingEntity 等覆写走 `super` 链必被强制 false。镜像跨维摆放用 `teleportTo`→`Entity.teleport`，不经此方法 → 不受影响。
- `ExampleMixin`：空壳。

### 3.10 `BiomeRestorer`（生物群系复原，v2.31）
- 读采集侧独立 `biomes.nbt`（`{timestamp, cells:{"qx,qy,qz":biomeId}}`，cell = 4×4×4 quart cell）；mtime 门控 + `prevIds` 快照 diff 出新增/变化 cell → 归组所在 chunk（`qx>>2, qz>>2`）入 `pendingChunks`。
- 逐 cell 语义：同 cell 所有方块 `getBiome` 必然相同（游戏存储保证）→ 只按 cell 填、绝不逐方块；cell key 用文件同款字符串，无跨端二进制打包约定。
- 写入**完全复用 vanilla `/fillbiome` 公开范式，零 Mixin / 零新包**：`chunk.fillBiomesFromNoise(resolver, randomState().sampler())`（resolver 对记录 cell 返回记录 holder，未记录返回 `chunk.getNoiseBiome` 现状 → 只覆盖不污染）→ `markUnsaved()`（落盘持久，块 unload→reload 从盘带回正确值）→ `chunkMap.resendBiomesForChunks(List.of(chunk))`（`ClientboundChunksBiomesPacket`，客户端即时重着色）。
- 生命周期：`MemoryWorldManager` 静态 `BIOME`，`onServerStart` 清空状态 → 首 tick 全量重读重填（支持 `resetOnLaunch` 重建）；tick 在 `CONTAINER` 后、`DELETION` 前。补填走 **tick-scan**（每 tick 扫 `pendingChunks` + `getChunkNow` 判加载，未加载块留待随传送加载后 ≤1 tick 补填），**不注册 CHUNK_LOAD 事件 → `StevexTest.java` 零改动**；限量 64 块/tick 防卡顿。注册表查不到 biome id → WARN 一次跳过。命令 `/memrestore` 一并 `forceRefresh`。
- v2.32：`cells/prevIds/pending` **按维分桶**（`pendingByDim`——chunk long 不编码维，主/下界同 chunk 坐标必须分桶防撞）；每 tick 只对 `level.dimension()` 维桶 diff/apply，群系永不跨维写入。

### 3.11 限制
仅支持单人内置服务器（`isDedicatedServer` 直接 return）；减量通道依赖采集端同版本配合（无握手/版本协商）。
- v2.32：镜像只还原 vanilla 三维（overworld/the_nether/the_end）；agent 在其它自定义维 → 节流告警暂停、数据在文件保留，回 vanilla 维自动恢复。已应用内容内存按维保留 + 区块落盘持久，镜像跨维切换不丢。
