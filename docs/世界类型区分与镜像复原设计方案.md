# 世界类型（维度）区分与镜像复原设计方案（v2.32）

> 状态：**已实施（v2.32，2026-09-06）**——采集端与记忆端全部改完、两端 offline `compileJava` 通过；
> 摘要已并入 `视觉api设计方案.md` 与 `已实现内容.md`。代码未提交。
>
> 已定案（用户选择）：**通用维度 id 全记录** + **单文件分维度桶** + **镜像跟随复原**。
>
> 实施路由按 **Design A（每 tick 驱动活动维 + 底部跨维传送）**，详见 §5.6。

## 1. 背景与缺口

视觉链路捕获时 agent 可能身处主世界 / 下界 / 末地（或任一 mod 维度），但现有数据**全部不含维度信息**：

| 位置 | 现状 |
|------|------|
| 采集端 `F3Api.java:48` | 唯一记录 `dimension` 的地方（`level.dimension()`），仅 `f3` 单点查询、与视觉链路无关 |
| 采集端 5 个视觉 store | `terrain.nbt` / `entities.nbt`（每次快照覆盖写）、`block_entities.nbt` / `biomes.nbt`（跨时间累积 union）、`containers.nbt`（低频提交）——**全部无维度字段、坐标裸键** |
| 复原端 `MemoryWorldManager.java:248` | 每 tick 只取 `server.getLevel(OVERWORLD)` 驱动，玩家只放在主世界；nether/end 虽是虚空生成器建好的维度、但从不去 |

后果：agent 在下界（或末地）采集的方块/实体/群系，以**主世界坐标系**放进记忆世界主世界——下界岩浆池悬在主世界天上、坐标还可能与主世界内容互相覆盖（两世界都从 (0,0) 附近起步，`block_entities.nbt`/`biomes.nbt` 这类累积 union 的裸 `"x,y,z"` 键必然碰撞）。

## 2. 关键事实（已核实）

- **坐标碰撞在累积文件里是必然的**：`block_entities.nbt`（BE union）、`biomes.nbt`（cell union）跨时间累加，若 agent 先主世界后下界，两维同坐标条目互相覆盖；快照式 `terrain.nbt`/`entities.nbt` 每次覆盖写只会"清掉上一维内容"。
- **群系 cell key 同样冲突**：刚实现的 `biomes.nbt` 用裸 quart `"qx,qy,qz"`，主/下界同 cell 撞键。
- **记忆端各复原器是"单维状态机"**：`TerrainRestorer`/`EntityRestorer`/`MemoryRestorer`（BE）/`BiomeRestorer`/`ContainerMemoryApplier` 各持一份 applied 表 / 指纹 / mtime，无法区分维。`MemoryCellReporter` 用 `terrain.appliedBlocks()` + `entities()` 对单一 level 求反向通道格。
- **跨维传送 = 现成公开路径**：记忆端已在用的 `player.teleportTo(ServerLevel, x,y,z, …, yaw, pitch, true)`（[Entity.java:3232](decompiled_src_vf/…/Entity.java)）经 `Entity.teleport(TeleportTransition)` 处理跨维；换目标 level 即完成维度切换，无新 API、无 Mixin。
- **nether/end 维度已建好**（v2.30 `createVoidWorldDimensions`，默认 `voidNetherEnd=true`）：下界/末地都以虚空生成器定型并写入 level.dat，首次进入即虚空空白画布——多维复原的前提已具备。记忆世界 nether/end ServerLevel 在玩家首次进入（传送触发）时惰性创建，用即建、生成器即虚空。
- **末影箱是玩家态、跨维全局**：真实 MC 里同一玩家的末影箱在主世界/下界/末地是同一个（`EnderInventory`）。记忆世界也只有一个本地玩家 → 末影箱记忆应**保持在文件顶层全局**，不随维度分桶。

## 3. 总体设计

在既有"采集 NBT → 记忆端 mtime 轮询"架构上加一层**维度命名空间**：

```
采集端（每快照 / 每次提交）
  记录当前维 dimensionId = level.dimension().identifier()
  写/改文件顶层 currentDimension + worlds:<dimId> 桶（见 §4）
  快照型 → 只覆写当前维的桶；累积型 → 当前维桶内 union；其余维桶原样保留
记忆端（镜像跟随）
  权威源 = terrain.nbt 顶层 currentDimension（每快照必写）
  → 把记忆玩家传送到同一维（记忆世界维度间传送，§5.3）
  → 只对"活动维"的 ServerLevel 驱动各复原通道；各复原器状态按维隔离
  → cells 反向通道/减量只对活动维，cells 文件带维标签防跨维误判
```

**核心取舍**：
- **单文件多桶**：文件名、自动探测路径、兄弟目录协议全不变；读一次全文件、按活动维取桶。文件格式自描述、向后兼容。
- **通用维度 id**：采集端对任意维度都如实记录；记忆端只对原生三维（overworld / the_nether / the_end）复现，未知维度桶**保留不删、跳过并节流 WARN**（不崩、留待扩展）。
- **镜像跟随而非并行**：记忆玩家永远站到 agent 所在的维，内容按维复原——玩家所见即 agent 所见；未进入的维内容在文件里永久保留，进入即铺。不做 3 个 ServerLevel 同时维护的并行模式（§决策 3 已选镜像）。

### 3.1 统一文件契约（v2.32）

所有"维度作用域"文件顶层变为：

```
{
  "currentDimension": "minecraft:overworld",   // 最近一次写入所属维（镜像权威 = agent 当前维）
  "worlds": {
    "minecraft:overworld": { <该维内容，形态=现文件正文> },
    "minecraft:the_nether": { <…> },           // 仅访问过的维出现
    ...
  }
}
```

各文件"该维内容"保持与今天**逐字相同**的正文形态（agent 姿态字段也移入桶内、每维一份）：

| 文件 | 桶内容 |
|------|--------|
| `terrain.nbt` | `{ agentPos, agentYaw, agentPitch, agentFov, dayTime, timestamp, blocks, deletions }` |
| `entities.nbt` | `{ agentPos, agentYaw, agentPitch, agentFov, dayTime, timestamp, entities }` |
| `block_entities.nbt` | `{ agentPos, agentYaw, agentPitch, agentFov, dayTime, blockEntities }` |
| `biomes.nbt` | `{ timestamp, cells }` |
| `containers.nbt` | 顶层 `{ version, currentDimension, worlds:{<dim>: { containers:{…} }}, enderInventory:{…} }`——`containers` 分桶；`enderInventory`（玩家态末影箱）保持顶层**全局**（§2 末影箱事实） |

> **向后兼容**：读取时若顶层无 `worlds` 键 → 视为旧文件，整份正文归为 `worlds["minecraft:overworld"]`，`currentDimension` 视为 overworld。旧存档/旧数据无缝衔接，无需迁移工具。

### 3.2 辅助约定（两端各自实现一份同名小工具）

`readWorlds(root) → (currentDimension, Map<dimId, CompoundTag>)`：无 `worlds` → 包一层 overworld。`writeWorlds(root, currentDimension, worlds)`。维度 id 用原始字符串（如 `minecraft:the_nether`），不做文件名/sanitize。

## 4. 采集端设计（stevex-template-1.21.11）

### 4.1 维度的来源与接线

渲染线程 `ObjectResolver.resolve` 有 `ClientLevel level`；`level.dimension().identifier().toString()` 即当前维 id（F3Api 已证）。各 store 的 `sync(...)` 增加一个 `String dimensionId` 形参；一次快照里所有 store 用**同一个** id（同一帧不可能跨维）。

### 4.2 快照型 store（VisionTerrainStore / VisionEntityStore）

现状：整文件覆盖写，无内存态。改法：加一个内存 `CompoundTag cache` 或每写前读旧文件合并——写 `root` 时先 `load()`（无内存态故读盘/缓存），置 `worlds[当前维] = 本次内容`、`currentDimension = 当前维`，其余维桶保留，整体写回。**语义变化点**：agent 换维只覆写自己那维的桶 → 上一维的"最后可见快照"不再被清掉（这正是分桶的价值；agent 回到该维时再覆写）。BE/实体姿态随桶存，每维一份。

### 4.3 累积型 store（VisionBlockEntityStore / VisionBiomeStore）

- `VisionBlockEntityStore`：内存 `entries` 由 `Map<String,StoredEntry>` 改为 **`Map<String(dim), Map<String(posKey), StoredEntry>>`**（外层 dim、内层 posKey 现键不变）；top-level 姿态字段同样移入每维桶。新增/更新/跳过判定逻辑不变，只在当前维子图内做。保存时把每维桶都写出（只有访问过的维有键），并写 `currentDimension`。
- `VisionBiomeStore`：`cells` 改为 `Map<String(dim), Map<String(cellKey), String>>`；其余同 v2.31 语义（union、逐 cell、新增>0 才写）。

### 4.4 容器（ContainerMemoryStore）

- `containers`（per-pos）移入 `worlds[当前维].containers`——提交路径（`ContainerMemoryTracker`/`ContainerApi`）在 commit 时取 `Minecraft.getInstance().level.dimension()` 定维（open→commit 几乎不可能跨维，提交瞬间取即可）。
- `enderInventory` **保持顶层全局**（玩家态，跨维同一末影箱）。
- 内存镜像 `containers` 同 4.3 改为按维嵌套；`enderPresent`/`enderItems` 仍全局。

### 4.5 快照响应 `storeStats`

`vision/snapshot` 响应顶层已有 `cameraPos/dimension` 吗？没有——现在**补 `"dimension": "minecraft:…"`**（agent 当前维，语义上与 store 写入的 currentDimension 一致），便于 agent/日志立刻知道这帧来自哪。store 统计结构不变。

### 4.6 反向通道 cells：加维标签

`memory_cells.bin` 头部（`MemoryCellReporter` 写 / `MemoryCellsReader` 读）在 `[4] version` 之后加 `dimensionId` 段，需**格式版本升级**：

```
[0..3]  magic "SCEL"
[4]     version = 2           // ← 升到 2
[5..8]  int 维 id 字节长度 L（含 UTF-8）
[9..9+L)  UTF-8 dimensionId    // 记忆侧活动维
…其后照旧 threshold / maxRayDist / count / count×long
```

采集侧 `MemoryCellsReader.CellsData` 增 `dimension` 字段；`DeletionJudge` 只对 `dimension == 本快照维` 的 cells 做删除判定——若记忆侧镜像落后（cells 还是上一维的）则本帧无删除证据（优雅降级，绝不跨维误删）。旧 version=1 文件读不到维 → 视为维度未知、删除证据置空（宁可不删，不误删）。

## 5. 记忆端设计（stevex-test-template-1.21.11）

### 5.1 活动维判定（权威源）

记忆端不改配置；`MemoryWorldManager.onServerTick` 每 tick 从 **terrain.nbt 顶层 `currentDimension`**（快照必写、最可靠）判定 agent 当前维：
- 读文件在 `TerrainRestorer` 内已完成 → 暴露 `activeDimensionId()`（文件缺失/未变时返回上次值；首 tick 文件缺失 → overworld 占位，不切）。
- 未知维度（不在原生三维白名单）→ **停在该维不切**、跳过该 tick 的复原与减量、节流 WARN；数据保留。

### 5.2 复原通道按维隔离 + 只驱动活动维

每个复原器由"单份状态"改为**"按维 Map 状态"**，每 tick 仍只被 manager 用活动 ServerLevel 调用一次：

| 复原器 | 状态变化 |
|--------|----------|
| `TerrainRestorer` | `applied: Map<BlockPos,String>` → `Map<String(dim), Map<BlockPos,String>>`；`appliedFingerprint/lastMtime` 同样按维。公开 `appliedBlocks()/mutationVersion()` 语义改为"当前活动维"（由 manager 传入的活动 level 决定，见 5.4） |
| `EntityRestorer` | FROZEN/已放置实体、uuid 表按维隔离；`entities()/mutationVersion()` 同语义 |
| `MemoryRestorer`（BE） | `entries/applied` 按维；`readPose` 只读**活动维桶**的姿态字段（每维桶自带 agentPos/…） |
| `BiomeRestorer` | `cells/prevIds/pendingChunks` 按维（pending 的 chunk long 不编码维，必须按维隔离防主/下界同 chunk 撞） |
| `ContainerMemoryApplier` | 只 apply 活动维桶的 `containers`；`enderInventory` 仍全局 apply 到本地玩家 |

**文件读取**：各复原器每轮 mtime 门控读到的已是 `worlds` 结构；活动维在 manager 层选定后，各复原器取 `worlds[活动维]` 做 diff/apply。非活动维桶不 apply（内容留在文件；镜像切回时再 apply）。已放置内容靠 chunk 落盘持久，切换不丢。

### 5.3 镜像传送（维度切换）

`onServerTick` 算出活动维后：
- `ServerLevel target = server.getLevel(key)`（3 个原生维 key 白名单直取：`Level.OVERWORLD/NETHER/END`；首次进入下界/末地时该 level 惰性创建、以虚空生成器定型）。
- 若 `activeDim != 当前玩家所在维`：调现有 `teleportToPose` 的底层 `player.teleportTo(target, x, y, z, Set.of(), yaw, pitch, true)`（§2 已核跨维公开路径），目标坐标/朝向 = 活动维桶里的 agent 姿态。传送后玩家四周虚空块加载 → 本 tick 起各复原器把活动维桶内容铺到该维。
- 玩家就绪一次性初始化（创造+飞行）不变；冻结 gamerule（`random_tick_speed`/时间/刷怪）是**世界级**的、三个维共享同一份存档级规则，进入即生效。
- 注意下界天光/迷雾等渲染由维度类型自带，复原内容落进下界后天然正确（这正是要修的"颜色/氛围错维"）。

> 实现确认（2026-09-06）：`server.getLevel(Level.NETHER/END)` 恒非空——记忆世界建档时
> `createLevels` 即构建全部三维（各自虚空生成器定型），非"首次进入才惰性建维"；`teleportTo` 跨维经
> `Entity.teleport(TeleportTransition)` 维度判等 → `teleportCrossDimension`（decompiled 已核），无需新 API /
> Mixin。渲染正确性（下界无天光 / 氛围）属运行期核验，见 §7 步骤 4。

### 5.4 减量 / cells 反向通道按活动维

- `MemoryCellReporter`：活动维不变——但它调 `terrain.appliedBlocks()`/`entities()` 必须取**活动维**那份（5.2 已改）；写 `memory_cells.bin` 头部带 `dimensionId=活动维`（§4.6 格式 version=2）。
- `DeletionApplier`：`DELETION.apply` 只对活动维做；删块同步清**活动维**的 BE 记录。`ContainerMemoryApplier` reconcile 同理限活动维。

### 5.5 旧文件兼容

所有读侧用 §3.2 `readWorlds`；旧单维文件自动当 overworld 桶 → 与今天行为逐字节等价，无迁移。

### 5.6 实施说明（Design A：每 tick 驱动活动维 + 底部跨维传送）

> 2026-09-06 已按本稿实施，`MemoryWorldManager` 实际路由为 **Design A**（对比稿曾权衡的"提前传送 + hold"：
> hold 会跳过推进文件读取的管线、有死锁风险，已弃用）：
>
> - **每 tick 驱动活动维 ServerLevel**，不做并行三维维护。活动维权威源 = `TERRAIN.activeDimensionId()`
>   （terrain.nbt 顶层 `currentDimension` 最近一次成功读取值）；原生三维 id 白名单（`Level.OVERWORLD/NETHER/END`）
>   直取 `server.getLevel(key)`；agent 在未知自定义维 → 300 tick 节流 WARN，降级驱动玩家当前所在 ServerLevel
>   （其内容已冻结 → 复原器近乎 no-op、不空转），agent 回 vanilla 维下一 tick 自动切回；无玩家时 overworld 兜底。
> - **复原顺序 = 先铺内容后传送**：terrain → entity → BE → container → biome → deletion → cells 全在该维 level
>   上跑完（各复原器只 apply `level.dimension()` 自己的维桶，坐标永不跨维错写），管线底部才把玩家
>   `player.teleportTo(活动维 level, x, y−eyeHeight, z, …, yaw, pitch, true)` 传过去——level 是另一维即由
>   `TeleportTransition` 完成 changeDimension。
> - **传送门控 = 跨维 ‖ 姿态变化**：玩家当前所在维 ≠ 活动维时无条件传送（同一姿态数值跨维也必须换，
>   否则 `samePose` 会误判"无需移动"而把玩家困在旧维）；同维时才与上次已应用姿态
>   （`lastAppliedPose`）比较，相同则跳过（防每 tick 冗余传送）。
> - **姿态交付**：每维桶姿态随该维首次驱动代际返回（serve 换代际 × 每维一次）；玩家未就绪或该维桶姿态
>   尚未读到 → `pose=null`，仅延迟 ≤1-2 tick 直至该维文件被读，无死锁。
> - **切换不丢内容**：各复原器 applied 表/union 在内存按维保留 + 区块落盘持久；镜像切回时经该维桶直接续铺。

## 6. 正确性论证

- **坐标不再跨维碰撞**：每维独立桶 + 按维隔离的 applied/union/pending——下界 (x,y,z) 永不碰主世界同坐标。
- **镜像锁步**：采集与复原都由 agent 单一视角驱动；记忆活动维 = agent 维（terrain 权威源），cells/删除只对同维，交叉维度永远没有数据交换窗口（cells 头部维标签兜底镜像瞬态落后）。
- **快照型不丢历史**：分桶后换维不再清掉上一维"最后可见"，agent 在维间往返时各维内容自洽。
- **减量安全**：cells 带维标签 + 只对活动维删除；镜像落后时宁缺勿滥。
- **纯累积不破坏**：各维 applied 表跨切换持久（内存内按维保留），被遮挡旧块在该维内仍被 tracking，不会变成永生幽灵。
- **非侵入**：未知维度跳过不崩；文件缺失行为不变；末影箱全局语义与真实 MC 一致。

## 7. 验证步骤

1. 两端 `./gradlew compileJava --offline` 通过（✅ 2026-09-06 已通过；步骤 2-7 为运行期验证、尚未执行）。
2. **采集端单维回归**：主世界走动、开容器、看群系——`terrain.nbt` 现为 `{currentDimension:"minecraft:overworld", worlds:{overworld:{…}}}`；`storeStats` 正常；`snapshot` 响应含 `dimension`。
3. **采集端跨维**：agent 经传送门进下界采集（方块/实体/容器/群系各来一点）再回主世界——两文件 `worlds` 都有 overworld 与 the_nether 桶，主/下界同坐标条目并存、互不覆盖。
4. **记忆端镜像**：删档重建记忆世界 → agent 在主世界 → 记忆玩家在主世界；agent 进下界并快照 → 记忆玩家被传送到下界虚空、下界内容按坐标铺开、雾/氛围为下界风格；回主世界 → 切回主世界且内容完好。
5. **反向通道**：记忆下界时 `memory_cells.bin` 头部 version=2 + 下界维标签，采集在下界快照能删除证据；把记忆端停掉让 cells 停留在"主世界"时，采集在下界不产生跨维误删。
6. **兼容**：把一份旧版无 `worlds` 的 terrain.nbt 放回 → 记忆端照常按 overworld 复现。
7. 控制台无新 WARN（除"未知维度跳过"若触发）。
